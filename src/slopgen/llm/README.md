# llm

**EN:** `client.py` — `ChatLLM`, one client for any OpenAI-compatible provider (JSON mode); provider presets in `PROVIDERS` (deepseek, gemini, openrouter, custom), popular models in `MODEL_PRESETS`. Connections are `LLMProfile` configs (`configs/llm/*.toml`), the active one chosen by `[llm].profile`; empty fields fall back to provider defaults via `resolve_provider`. API keys live in `.env` only. With `web_search` on, `complete_json` runs a tool-calling loop (`_run_tools`) offering the real `web_search` tool from `tools.py` (keyless DuckDuckGo) — the model calls it, results are fed back, then it answers.

The rest are task-specific prompt modules, each owning one job and its output contract: `characters.py` — turn a reference photo into an appearance blurb (vision), invent missing cast fields, and compile a character into the token-dense English `visual_prompt` that gets substituted into shot prompts. Its `world` flag switches between the two things "character" means: a drama's person (age, looks, a personality the drama writes) and a world's LOOK — which need not be human, need not have a face, and need not be ONE, since an entry may stand for a body of identical faceless figures or a whole kind of them (`_PLURALITY`). Fill and compile both narrow accordingly: nothing personal in a group's prompt, singular phrasing so the shot decides how many are in it, and for a world nothing invented beyond the looks at all — a temper or a history made up here would be a fact about the world stored where the writer never reads it. `rewrite.py` — the AI edit line on breakpoints: `rewrite` reworks a list of text lines, `rewrite_scenes` reworks a whole scene list and may reorder, merge, split, add or drop scenes while carrying each one's identity. `censor.py` — rewrites profane SUBTITLE lines into harmless ones (the audio is untouched), screening by regex first so a clean video costs no request at all. `lore.py` — compiles a fandom's markdown into the canon sheet: one call, the whole lore in, an INVENTORY out (premise, register, rules, taboos, glossary, figures, places, factions, timeline), rendered by `render_canon` in reading order with empty sections dropped — a heading with nothing under it reads to a model as "this world has no places". `recompile_if_stale` mirrors `characters.recompile_if_dirty` but compares checksums instead of trusting a flag, since nothing raises one when the operator edits `lore.md` in their own editor. The **taboos** section is the one that is inferred rather than copied, and the one that stops the narrator furnishing an invented world out of ours. Two things sharing a NAME are two entries, and the sheet is told so outright: where two factions each keep an office, a body or a custom of the same name, folding them into one line is how one side ends up wearing the other's practice as fact, with nothing downstream able to tell that it is wrong — the shipped world has hunters on both sides of a border who work differently, and a merged line gave one of them the other's method. Since the sheet is CACHED against a checksum, the checksum carries a compiler version too (`config.loader.CANON_COMPILER_VERSION`): without it a fix to this prompt would reach only the worlds whose lore happens to be edited afterwards.

`write_brief` is the other half of the module — the TUI's "write the brief" helper, which proposes or rewrites what a fandom video is about. Three things it is careful with. It reads the RECORDS rather than the compiled sheet wherever they fit, because it runs once per press and the sheet's saving is worth little against being unable to tell two similarly-named things apart. The operator's INSTRUCTION decides the shape and the length of what comes back, with no cap: it used to say "two to five sentences, no more" and "never write the narration itself", so an instruction asking for the whole thing written out came back compressed into a summary of itself — and the video's writer now reads a long brief as the piece and a short one as a topic (`stages/fandom_script.BRIEF_RULE`), which makes the choice the operator's. And it is told the video's LENGTH, including when there is none: with the length free it is chosen off this very brief (`length.py`), so a brief written to a habitual five sentences would quietly decide that the video is short.

`usage.py` + `router.py` — **what a run spends, and who it spends it on.** A provider's dashboard reports a day; a video costs what it costs, and the two are not the same question. So every call through `ChatLLM` is recorded into the run's `UsageLedger` as it happens — stage, prompt kind, model, tokens in, tokens the provider served out of its own prompt CACHE, tokens out, seconds, and whether it was a first attempt or a retry. Retries are separate rows on purpose: a stage that re-asks pays the whole context again, and folding the second attempt into the first hides the one number worth seeing. The whole ledger is written into `checkpoint.json` on every save and printed by `slopgen usage <run dir>`. The cache column is why prompt-cache work is checkable rather than believable: a cache matches on the PREFIX and stops at the first difference, so invariant material sitting behind a per-window rule caches nothing, and `cached_tokens` says so. Money is deliberately not built in — prices change, differ per provider and differ between a cache hit and a miss, so they are three fields on the profile (`price_in` / `price_cached` / `price_out`, USD per million tokens) and an unpriced profile simply reports tokens.

`router.py` is the other half: which model answers which call. Every call already announces what it is (`complete_json("fandom_script", …)`), so routing needs no new plumbing at all — `[llm.stage_profiles]` maps that kind to a profile name and `LLMRouter` stands where the single client used to. The reason to want it is that the calls are not alike: writing a script off a whole world is what an expensive model is for, while compiling one character's looks into image tags, naming a finished video or turning a shot into a stock query is errand work — and on a fandom run the errands outnumber the writing. It fails soft in every direction: an unlisted kind, a profile that does not exist and a profile whose key is missing all fall back to the active one, because a wrongly-configured cheap model must never cost the operator a script.

`length.py` — **how long should this be, when nobody said.** A duration of `0` is the operator declining to buy a length: the model chooses one from the material. That is one behaviour with two implementations, and the split is what the modes actually need rather than a compromise. An **info** clip needs no call at all — its script is a single request and the finished video is exactly as long as the narration turned out, so nothing ever has to know the number in advance and the writer is simply told to choose (`stages/script.FREE_LENGTH_RULE`). A **beat** mode cannot do that: the length is what the shot list is CUT from, so it has to exist before a word is written, and this is the one small call that answers it. The number it is handed that it could not work out for itself is how long the BRIEF would take to say aloud — which is the whole question for a brief that is already a finished text (six rules and three accounts written to be read out is as long as reading them out takes) and says nothing at all for a brief that merely names a subject. Given both the text and its spoken length, the model can tell those two cases apart instead of reaching for a round number. It never raises and never returns zero: a failed or nonsensical answer falls back to `DEFAULT_FREE_S`, because the caller is about to cut a shot list out of whatever comes back.

`lookup.py` — the briefing pass for **user-assisted search**: given the shots the operator has to go and find, it writes each one a one-sentence brief in the content language, 3-5 short English stock queries, and a `want` of `photo` or `video`. It exists because the two halves of searching split unevenly: slopgen has no eye for whether a clip is usable, but it does know what each beat needs and what words are likely to surface it — and those words are not the shot prompt. A drama's beat ("Марта bends over the sorting table, lamplight catching the wax seals, slow push-in") and a stock index ("woman sorting mail warm light") are different languages, so this is a translation, not a copy; the system prompt spells that out, bans camera jargon, proper nouns and word-for-word translation, and asks for varied queries so a dead first one is not a dead shot. `want` is decided per shot because it belongs to the material — a held detail wants a still, a process wants motion — and is advice only: `pipeline/manual.attach` records whatever file actually arrives. Calls are batched at `BATCH = 20` (a hundred shots in one response come back with the tail written as "similar to the above"), and a failed batch returns no entries at all, so the caller keeps the shot description it already had.

`style.py` — the operator's description of how the video should LOOK, compiled into the tags that get glued onto every generated prompt. It exists because neither end of what people write survives being pasted in raw: «аниме» reaches a generator as one foreign token it prints across the frame, and even as "anime" it is a word rather than a look — what pins the look is the handful of tags the word stands for (cel shading, flat colour, thick linework, painted backgrounds). Three paragraphs about 16mm grain have the opposite problem: they are sentences, they mix in things about the story, and appended to forty shot prompts they out-weigh the shots. So both go through one pass — expand the short one, boil the long one down — capped at `MAX_TAGS` (16) so the look never crowds out the shot, the same crowding the drama's appearance budget guards against. The contract it defends is STYLE ONLY: the compiled tags ride on prompts that already carry a subject, so one stray noun would put that noun in all forty shots. Non-Latin words are stripped whatever the model returns, the result is cached on disk by text, and a failed call falls back to the operator's own words when they were written in English and to nothing when they were not — a shot without style tags is still a shot, one captioned in Cyrillic is ruined.

`tools.py` holds both kinds of function tool. Stateless ones (`web_search`) live in the module-level `TOOLS` / `TOOL_EXECUTORS` registry; one bound to a single run's data cannot, so `make_lore_lookup` builds `lore_lookup` per run — a librarian LLM that reads the WHOLE lore to answer one question in the records' own wording. That full reading per call is exactly why it is the last resort rather than the only channel: the canon sheet (in every window) and the outline's per-stretch detail lists carry the bulk of the world for free, and a search tool alone has the classic retrieval failure — the writer never asks about the currency it does not know exists. Its system prompt keeps the archivist inside the world too: unrecorded is unrecorded *there*, never "the author never specified", and a failed lookup returns a sentence telling the writer to write around the detail rather than taking the script down.

**RU:** `client.py` — `ChatLLM`, один клиент для любого OpenAI-совместимого провайдера (JSON-режим); пресеты провайдеров в `PROVIDERS` (deepseek, gemini, openrouter, custom), популярные модели в `MODEL_PRESETS`. Подключения — профили `LLMProfile` (`configs/llm/*.toml`), активный выбирается `[llm].profile`; пустые поля подменяются дефолтами провайдера через `resolve_provider`. Ключи API — только в `.env`. При включённом `web_search` `complete_json` запускает цикл tool-calling (`_run_tools`) с настоящим инструментом `web_search` из `tools.py` (бесключевой DuckDuckGo) — модель его вызывает, результаты возвращаются, затем она отвечает.

Остальные модули — промпты под конкретные задачи, каждый со своим контрактом ответа: `characters.py` — превратить фото в описание внешности (vision), придумать недостающие поля каста и скомпилировать персонажа в плотный английский `visual_prompt`, который потом подставляется в промпты кадров. Флаг `world` переключает между двумя смыслами слова «персонаж»: человек драмы (возраст, внешность, характер, который драма и пишет) — и ВНЕШНОСТЬ мира, которая не обязана быть человеком, не обязана иметь лицо и не обязана быть ОДНА: запись может означать толпу одинаковых безликих фигур или целый вид (`_PLURALITY`). Заполнение и компиляция сужаются соответственно: у группы в промпте ничего личного, формулировка в единственном числе — сколько их в кадре, решает кадр, — а для мира вообще ничего не выдумывается сверх внешности: придуманные здесь нрав или биография были бы фактом мира, положенным туда, где сценарист его не читает. `rewrite.py` — ИИ-строка на брейкпоинтах: `rewrite` переписывает список текстовых строк, `rewrite_scenes` — весь список сцен, с правом переставить, склеить, разбить, добавить и удалить, сохраняя тождество каждой. `censor.py` — переписывает матерные строки СУБТИТРОВ в безобидные (озвучка не трогается), сначала просеивая регуляркой, так что чистое видео не стоит ни одного запроса. `lore.py` — собирает markdown фандома в канон-справку: один запрос, весь лор внутрь, ОПИСЬ наружу (что это за мир, как здесь говорят, правила, табу, глоссарий, люди, места, группы, хронология), которую `render_canon` печатает в порядке чтения и выбрасывает пустые разделы — заголовок без содержимого модель читает как «мест в этом мире нет». `recompile_if_stale` повторяет `characters.recompile_if_dirty`, только сравнивает контрольные суммы, а не верит флажку: никакой флажок не поднимется, когда оператор правит `lore.md` в своём редакторе. Раздел **табу** — единственный, который не выписывается, а выводится, и именно он не даёт рассказчику обставлять выдуманный мир вещами из нашего. Две вещи с одним ИМЕНЕМ — две записи, и справке это сказано прямо: если у двух сторон есть одноимённая должность, служба или обычай, склейка их в одну строку — это способ надеть на одну сторону практику другой, причём как факт, который ниже по конвейеру уже никак не опознать; в поставляемом мире ловчие есть по обе стороны межи и работают по-разному, а склеенная строка отдала одним метод других. Справка КЕШИРУЕТСЯ по контрольной сумме, поэтому в сумму заложена и версия компилятора (`config.loader.CANON_COMPILER_VERSION`): без неё исправление этого промпта дошло бы только до тех миров, чей лор потом случайно правили.

`write_brief` — вторая половина модуля: помощник «написать замысел» из TUI, который предлагает или переписывает, о чём фандомное видео. Осторожен он в трёх местах. Читает САМИ ЗАПИСИ, а не собранную справку, пока они влезают: вызывается он раз на нажатие, и экономия справки не стоит неспособности различить две одноимённые вещи. ИНСТРУКЦИЯ оператора решает форму и длину ответа, без потолка: раньше там стояло «две-пять фраз, не больше» и «никогда не пиши саму озвучку», поэтому просьба расписать всё целиком возвращалась ужатой в пересказ самой себя, — а сценарист видео теперь читает длинный замысел как сам ролик, а короткий как тему (`stages/fandom_script.BRIEF_RULE`), и значит выбор принадлежит оператору. И ему называют ДЛИНУ видео, в том числе когда её нет: при свободной длине она выбирается по этому же замыслу (`length.py`), так что замысел, написанный по привычке в пять фраз, тихо решил бы, что ролик короткий.

`usage.py` + `router.py` — **сколько прогон тратит и на что.** Панель провайдера показывает сутки; ролик стоит столько, сколько стоит, и это разные вопросы. Поэтому каждый вызов через `ChatLLM` по ходу дела пишется в `UsageLedger` прогона: стадия, вид промпта, модель, токены на входе, токены, которые провайдер отдал из своего КЕША промптов, токены на выходе, секунды и то, первая это попытка или повтор. Повторы — отдельные строки, и намеренно: перезапрос платит за весь контекст заново, а сложенная в одну с первой попыткой вторая прячет ровно то число, ради которого всё и считается. Вся книга пишется в `checkpoint.json` при каждом сохранении и печатается командой `slopgen usage <папка прогона>`. Колонка кеша — то, из-за чего кеширование промптов можно проверить, а не принять на веру: кеш совпадает по ПРЕФИКСУ и обрывается на первом различии, так что неизменный материал, стоящий за правилом окна, не кешируется вовсе, и `cached_tokens` об этом и говорит. Денег внутри намеренно нет: цены меняются, различаются у провайдеров и различаются для попадания в кеш и промаха, поэтому это три поля профиля (`price_in` / `price_cached` / `price_out`, доллары за миллион токенов), а профиль без цен просто показывает токены.

`router.py` — вторая половина: какая модель отвечает на какой вызов. Каждый вызов и так называет себя (`complete_json("fandom_script", …)`), так что маршрутизации не нужно никакой новой проводки — `[llm.stage_profiles]` сопоставляет этот вид имени профиля, а `LLMRouter` встаёт туда, где был единственный клиент. Нужно это потому, что вызовы неодинаковы: писать сценарий по целому миру — работа для дорогой модели, а скомпилировать внешность одного персонажа в теги, назвать готовый ролик или превратить кадр в запрос к стоку — поручение, и в фандомном прогоне поручений больше, чем письма. Ломается мягко во все стороны: невнесённый вид, несуществующий профиль и профиль без ключа одинаково откатываются к активному — неверно настроенная дешёвая модель не должна стоить оператору сценария.

`length.py` — **сколько это должно идти, если никто не сказал.** Длительность `0` — это отказ оператора покупать длину: модель выбирает её сама, по материалу. Поведение одно, реализации две, и это не компромисс, а то, что режимам реально нужно. **Инфо**-ролику запрос не нужен вовсе: его сценарий — один запрос, а готовое видео ровно такой длины, какой вышла озвучка, так что число заранее никому не требуется, и сценаристу просто говорят выбрать самому (`stages/script.FREE_LENGTH_RULE`). **Битовый** режим так не может: длина — это то, из чего нарезается список кадров, поэтому она обязана существовать до первого написанного слова, и отвечает на это один маленький запрос. Единственное число, которое он получает и не мог бы вывести сам, — сколько времени займёт произнести вслух сам БРИФ. Для брифа, который уже готовый текст, это и есть весь ответ (шесть правил и три рассказа, написанные, чтобы их прочли вслух, идут ровно столько, сколько их читать), а для брифа, который лишь называет тему, — не значит ничего. Получив и текст, и его длину в секундах, модель различает эти два случая вместо того, чтобы хвататься за круглое число. Не падает и не возвращает нуля: сорвавшийся или бессмысленный ответ откатывается к `DEFAULT_FREE_S`, потому что вызывающая сторона сейчас будет резать список кадров из того, что вернулось.

`lookup.py` — проход-задание для **user-assisted поиска**: получив кадры, которые оператору предстоит найти, он пишет каждому бриф в одну фразу на языке контента, 3-5 коротких английских запросов для стоков и `want` — `photo` или `video`. Он появился потому, что поиск делится на половины неровно: у слопгена нет глаза, чтобы понять, годится ли клип, но он знает, что нужно каждому биту и какими словами это вероятнее всего найдётся, — а слова эти не совпадают с промптом кадра. Бит дорамы («Марта склоняется над сортировочным столом, свет лампы ложится на сургучные печати, медленный наезд») и индекс стока («woman sorting mail warm light») — разные языки, так что это перевод, а не копирование; системный промпт так и говорит, запрещая операторский жаргон, имена собственные и пословный перевод и требуя разных по широте запросов, чтобы пустая выдача по первому не означала пустого кадра. `want` решается по каждому кадру, потому что принадлежит материалу — задержанная деталь просит неподвижного кадра, процесс просит движения, — и остаётся советом: `pipeline/manual.attach` записывает тот файл, который реально принесли. Запросы идут пачками по `BATCH = 20` (сотня кадров в одном ответе возвращается с хвостом «аналогично предыдущим»), а сорвавшаяся пачка не возвращает ничего, поэтому вызывающая сторона остаётся с тем описанием кадра, что у неё уже было.

`style.py` — описание того, как должно ВЫГЛЯДЕТЬ видео, скомпилированное в теги, которые дописываются к каждому промпту генерации. Он нужен потому, что ни один край того, что пишут люди, не переживает вставки как есть: «аниме» приходит в генератор одним иностранным токеном, который тот печатает поперёк кадра, а даже «anime» — это слово, а не вид; вид держится на горстке тегов, за которые слово стоит (cel shading, плоский цвет, толстый контур, рисованные фоны). У трёх абзацев про зерно 16 мм беда обратная: это предложения, в них намешано и про сюжет, а дописанные к сорока промптам они перевешивают сами кадры. Поэтому оба идут через один проход — короткое разворачивается, длинное сваривается — с потолком `MAX_TAGS` (16), чтобы вид не вытеснил кадр: та же теснота, от которой драму защищает бюджет внешности. Контракт, который он держит, — ТОЛЬКО СТИЛЬ: скомпилированные теги едут на промптах, где субъект уже есть, так что одно лишнее существительное попало бы во все сорок кадров. Нелатинские слова вырезаются, что бы модель ни вернула, результат кешируется на диске по тексту, а сорвавшийся запрос откатывается к собственным словам оператора, если те написаны по-английски, и ни к чему, если нет: кадр без тегов стиля — всё ещё кадр, кадр с кириллицей поперёк — испорчен.

В `tools.py` живут инструменты обоих видов. Не зависящие от прогона (`web_search`) лежат в реестре модуля `TOOLS` / `TOOL_EXECUTORS`; привязанный к данным одного прогона так не может, поэтому `make_lore_lookup` собирает `lore_lookup` под прогон — нейронку-библиотекаря, которая читает ВЕСЬ лор ради ответа на один вопрос, в формулировках самих записей. Это полное чтение на каждый вызов и есть причина, по которой инструмент — последняя очередь, а не единственный канал: канон-справка (в каждом окне) и списки деталей по отрезкам из прохода-плана доносят основную массу мира бесплатно, а один только поиск даёт классический провал — сценарист никогда не спросит про валюту, о существовании которой не знает. Системный промпт держит архивариуса внутри мира: незаписанное незаписано *там*, а не «автор не уточнял»; а сорвавшийся запрос возвращает фразу с советом обойти деталь, вместо того чтобы уронить сценарий.
