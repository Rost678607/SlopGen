# config

**EN:** Pydantic models for every config kind (`models.py`) and the loader (`loader.py`). `ConfigStore` scans `configs/` — the global file plus content types, ads, accounts, presets, visuals profiles, LLM profiles, characters, orchestrations and fandoms — and resolves run parameters with the priority CLI > preset > account defaults > global defaults; `active_llm_profile()` picks the LLM connection. `RunParams` is the single validated object the rest of the app consumes: besides the obvious knobs it carries the ad-hoc `manual_ad` / `manual_visuals` / `manual_cast` / `manual_orchestration` built in the TUI, the `breakpoints` a run should park on, the content controls (`visual_notes`, `visual_style`, `clean_subtitles`) and the montage `filters` — `{effect: dose}` laid over the finished cut (see `media/filters`), which unlike the other two is asked of ffmpeg rather than of a model, and so holds in every mode and from every source. For fandom mode it adds `fandom` (the world's folder name), `fandom_voice` (`resident` / `chronicler` / `usher`) and `fandom_invent` — how far the writer may add to the world where its records stop, in three positions rather than two: `no` (the default, the records are the whole world), `gaps` (invent only where a beat cannot be written otherwise, and only the smallest ordinary detail that unblocks it) and `free` (furnish the world at will). All three still forbid contradicting a record, inventing the SUBJECT of the piece, coining a name for something the records leave unnamed, and settling what they leave open (see `stages/fandom_script.GAP_NONE`/`GAP_GAPS`/`GAP_FREE`). It was a bool until the two-position version turned out to fail in one direction only — told merely that it may invent, a model invents the thing the video is about — so a stored `true` validates forward into `gaps`, the bounded reading, rather than the one that misbehaved; everything the drama block means means the same there, `scenario` included — it is just a brief about a world rather than a plot.

**In a visuals profile, WHO supplies the material is orthogonal to WHAT it is.** `manual = true` is a flag on the background (and on the foreground) rather than a source of its own, because the operator can step into either family and what they end up doing differs: a `stock_*` source found by hand is a **search** (slopgen briefs them and hands over queries), an `ai_*` source made by hand is a **generation** (slopgen writes the prompt), and `local_*` ignores the flag entirely — those files are already on disk. `manual_kind(source, manual)` is the one place that mapping lives, returning `"search"` / `"generate"` / `""`, and both footage stages route on its answer. `ai_model` is ignored wherever `manual` is set: there is no generator left to name. This replaced an earlier `ai_model = "manual"` hack, which could only express the generation half and hid a question about supply inside an answer about generators.

**Fandoms are the one config kind that is a DIRECTORY** (`configs/fandoms/<name>/`), so `_load_fandoms` does the walking instead of `_load_dir`: the folder name is the identity whatever the TOML says, `fandom.toml` is optional (a folder of markdown is a valid world with every default), and the world's own cast is loaded from `<folder>/characters/` with the same `CharacterConfig` the global library uses — filled in differently, see below. `fandom_docs` resolves the reading order (`docs`, else every `*.md` sorted; a name pointing at nothing is skipped rather than taking the world down), `read_lore` concatenates the documents under their own filename headings so both the writer and the librarian tool can tell one from another, `lore_sha` hashes that text, and `write_fandom` persists the settings back (runtime-only `root`/`cast` are excluded by the model). `FandomConfig.canon` is to the lore what `CharacterConfig.visual_prompt` is to an appearance — an LLM-compiled digest — except that its freshness is a checksum (`docs_sha`) rather than a `dirty` flag, because lore gets edited in an outside markdown editor where nothing would ever raise a flag. `envfile.py` writes single variables into `.env` (API keys entered in the TUI). **`viewer_role` is the one field only one narrator reads.** The `usher` voice speaks TO someone, and that someone has to be a person standing in the world; this says which person, in the world's own words. Empty is the normal case rather than a hole: the canon sheet compiles a `WHO A NEWCOMER HERE BECOMES` line out of any lore handed to it (`llm/lore`), and where there is no sheet the writer settles the same question in-window — so a world nobody has annotated still addresses one consistent person instead of a different one per stretch. The field is the override for a guess the operator did not want, and `RunParams.viewer_role` overrides it again per run, because one world holds many positions and which one is being spoken to is a property of the video, not of the world. What it fixes is the ADDRESSEE and never the subject: a piece told to a newcomer may be entirely about what newcomers are not shown.

**A world's character is a LOOK, not a person.** The drama and the fandom share `CharacterConfig` and mean different things by it, which is why the model carries fields neither mode uses in full. A drama invents its cast, so a character there is one person with an `age` and a personality the drama is free to write. A world's character is only ever what exists in that world and how it is recognised on screen: no age — `_load_fandoms` strips the field rather than merely leaving it unwritten, so a hand-edited or pre-rule file cannot smuggle a value into a mode with no field to show it back in; age that shows on a thing shows in its looks — and no personality at all — that goes in the lore documents, in prose, where every other fact about the world already lives and where the writer actually reads it. Nothing in the pipeline reads a temper off a character sheet; it reads a picture. Nor is a world's character necessarily ONE of anything, hence `plurality`: `one` (this specific character, this face in every shot), `many` (a body of visually identical, faceless figures — the wardens, the carriers, all wearing one look and none of them named) or `class` (a whole race, caste or model of machine, described by what any member of it shares). The distinction is not cosmetic: the compiled `visual_prompt` is substituted in place of the name in every shot, so a group's prompt must be one singular figure carrying nothing personal — otherwise "three wardens" renders as three men with the same scar.

`configs/voices/*.toml` is the newest config kind and the odd one out: a `VoiceConfig` is a card plus the audio sample sitting next to it, and because cloning is zero-shot — no training step, no model artifact — the card **is** the voice rather than a pointer to one. `text` is typed by hand on purpose: a transcript lifted off the sample by a recognizer does not merely contain errors, it makes the model drift, and in the measured worst case speak words from the SAMPLE in the middle of a synthesized line. `[tts]` in the global file gained `engine` plus a subsection per engine, and `paths.models` for the weights `slopgen models` downloads; `ContentTypeConfig.voices` still maps a language to a voice name, but the name is now read by whichever engine is speaking — a catalogue id or the name of a `configs/voices/` clone, one namespace, resolved by whether a card of that name exists.

**A world's FRAME BASE** lives in `configs/fandoms/<name>/frames/`: one TOML card per picture with the picture itself beside it, loaded by the same `_load_dir` the cast uses. A card holds two texts that must not be confused — `prompt` is the English generation prompt, `description` is prose in the world's own language for the model that matches cards to beats, and the description carries names but never looks, because appearance is already written once in `characters/<name>.toml` and a second copy would drift out of step with it. It also holds `targets`: named rectangles on the picture, in fractions of it, which is what lets one wide still become four shots (see `pipeline/framebase`). There is no `dirty` flag — nothing here is LLM-compiled, the picture IS the artifact — but the geometry can go stale if the file behind a card is swapped, so `file_sha` is a checksum in the spirit of `docs_sha`, and `card_is_stale()` is what asks. `write_frame_card()`, `frames_dir()` and `file_sha()` sit beside `write_fandom()` as the only core writers.

**A CATALOGUE OF PIECE SHAPES** lives in `configs/shapes/*.toml`, one file per catalogue, each holding several `[[shapes]]` — a `name`, a one-line `use_when`, and `ends`, which is what earns the whole config kind. The fandom planner picks one form per video (`stages/fandom_script.plan_spine`), and the four it used to choose between were prose inside a prompt: closed on purpose, because a model asked to pick a form freely picks "an atmospheric exploration of", which is the survey the plan exists to prevent — but closed in the wrong PLACE, since the forms a world affords are a fact about the world. A place with a duty roster and a place with a bestiary want different ones and neither is a code change. `ends` is the field that makes a shape more than a label: the general rule for these pieces is one turn late and then a line that stops, and it is simply wrong for some of them — a piece offering a choice ends ON the list of options, a vignette ends unfinished — so whatever a shape writes there replaces it, and `turn` does the same for the turn. A world names its catalogue with `shapes = "<name>"` in its `fandom.toml`, a run overrides that with `--shapes`, and `--shape` forces one form for one video, which is how a run of alike videos is made. Anything unnamed falls back to the shipped `default`, and a checkout with no catalogue at all falls back to two forms defined in code — enough to keep the mode working, deliberately not a second copy of the shipped file to drift against it.


**RU:** Pydantic-модели всех видов конфигов (`models.py`) и загрузчик (`loader.py`). `ConfigStore` сканирует `configs/` — глобальный файл плюс типы контента, реклама, аккаунты, пресеты, профили видеоряда, профили нейронок, персонажи, оркестрации и фандомы — и резолвит параметры прогона с приоритетом CLI > пресет > дефолты аккаунта > глобальные; `active_llm_profile()` выбирает LLM-подключение. `RunParams` — единый валидированный объект, которым пользуется всё остальное: кроме очевидных ручек он несёт ad-hoc `manual_ad` / `manual_visuals` / `manual_cast` / `manual_orchestration` из TUI, список `breakpoints`, на которых прогон должен встать, контентные ручки (`visual_notes`, `visual_style`, `clean_subtitles`) и монтажные `filters` — `{эффект: доза}`, накладываемые на готовый монтаж (см. `media/filters`); в отличие от первых двух это просят не у модели, а у ffmpeg, поэтому работает во всех режимах и с любым источником. Для режима фандома добавляются `fandom` (имя папки мира), `fandom_voice` (`resident` / `chronicler` / `usher`) и `fandom_invent` — насколько сценаристу позволено дописывать мир там, где кончаются записи, в трёх положениях вместо двух: `no` (по умолчанию — записи и есть весь мир), `gaps` (придумывать только там, где бит иначе не написать, и только самую мелкую бытовую подробность, которая его расшивает) и `free` (дообставлять мир свободно). Во всех трёх положениях по-прежнему нельзя противоречить записям, придумывать то, ПРО ЧТО ролик, давать имя тому, что записи оставили безымянным, и разгадывать оставленное ими открытым (см. `stages/fandom_script.GAP_NONE`/`GAP_GAPS`/`GAP_FREE`). Это был bool, пока не выяснилось, что версия на два положения ломается только в одну сторону — модели, которой просто сказали, что придумывать можно, придумывает то, про что ролик, — поэтому сохранённый `true` валидируется вперёд в `gaps`, в ограниченное прочтение, а не в то, которое вело себя плохо; всё остальное из драмовского блока значит там ровно то же, включая `scenario`, — просто это бриф про мир, а не про сюжет.

**В профиле видеоряда КТО поставляет материал ортогонально тому, ЧТО это за материал.** `manual = true` — это флаг на фоне (и на переднем плане), а не отдельный источник: оператор может вмешаться в любое семейство, и делает он при этом разное. Найденный руками `stock_*` — это **поиск** (слопген пишет задание и выдаёт запросы), сделанный руками `ai_*` — это **генерация** (слопген пишет промпт), а `local_*` флаг игнорирует вовсе: эти файлы уже лежат на диске. `manual_kind(source, manual)` — единственное место, где живёт это соответствие; он возвращает `"search"` / `"generate"` / `""`, и обе стадии видеоряда ветвятся по его ответу. `ai_model` игнорируется везде, где выставлен `manual`: называть больше нечего. Это пришло на смену костылю `ai_model = "manual"`, который умел выразить только генерацию и прятал вопрос о поставщике внутри ответа про генераторы.

**Фандом — единственный вид конфига, который является ДИРЕКТОРИЕЙ** (`configs/fandoms/<имя>/`), поэтому его обходит `_load_fandoms`, а не `_load_dir`: имя папки и есть тождество, что бы ни было в TOML; `fandom.toml` необязателен (папка с markdown — уже валидный мир со всеми дефолтами); собственный каст мира грузится из `<папка>/characters/` тем же `CharacterConfig`, что и общая библиотека, — но заполняется иначе, см. ниже. `fandom_docs` определяет порядок чтения (`docs`, иначе все `*.md` по алфавиту; имя, указывающее в никуда, пропускается, а не роняет мир), `read_lore` склеивает документы, каждый под заголовком со своим именем файла, чтобы и сценарист, и инструмент-архивариус отличали один от другого, `lore_sha` считает по этому тексту контрольную сумму, а `write_fandom` пишет настройки обратно (рантайм-поля `root`/`cast` исключает сама модель). `FandomConfig.canon` — это для лора то же, что `CharacterConfig.visual_prompt` для внешности, скомпилированная нейронкой выжимка, с одной разницей: свежесть определяется контрольной суммой (`docs_sha`), а не флажком `dirty`, потому что лор правят во внешнем markdown-редакторе, где никакой флажок не поднимется. `envfile.py` пишет отдельные переменные в `.env` (ключи, введённые в TUI). **`viewer_role` — единственное поле, которое читает только один рассказчик.** Голос «обращается к тебе» говорит КОМУ-ТО, и этот кто-то обязан быть человеком, стоящим в мире; поле называет, каким именно, словами самого мира. Пусто — это нормальный случай, а не дырка: канон-компилятор выводит строку `WHO A NEWCOMER HERE BECOMES` из любого поданного ему лора (`llm/lore`), а там, где листа нет, сценарист решает тот же вопрос прямо в окне, — поэтому мир, который никто не размечал, всё равно обращается к одному и тому же человеку, а не к разному в каждом отрезке. Поле — это переопределение догадки, которая оператора не устроила, а `RunParams.viewer_role` переопределяет его ещё раз на прогон: в одном мире много положений, и какое из них слушает — свойство ролика, а не мира. Задаёт оно АДРЕСАТА и никогда тему: ролик, обращённый к новичку, может быть целиком про то, куда новичка не пускают.

**Персонаж мира — это ВНЕШНОСТЬ, а не человек.** Драма и фандом делят один `CharacterConfig` и понимают под ним разное — потому в модели и есть поля, которыми каждый режим пользуется не целиком. Драма свой каст выдумывает, поэтому персонаж там — один человек с `age` и характером, который драма вольна написать. Персонаж мира — только то, что в этом мире есть, и то, по чему его узнают в кадре: никакого возраста — `_load_fandoms` поле не просто не пишет, а срезает при загрузке, чтобы правленный руками или написанный до этого правила файл не протащил значение в режим, где его негде показать; возраст, который виден, виден во внешности, — и никакого характера вообще, характер идёт в лор-документы, прозой, туда же, где живут все остальные факты мира и где сценарист его действительно читает. Ничто в конвейере не считывает нрав с карточки персонажа — оно считывает картинку. И персонаж мира вовсе не обязательно ОДИН, отсюда `plurality`: `one` (конкретный персонаж, одно и то же лицо в каждом кадре), `many` (толпа визуально одинаковых безликих фигур — стражи, почтальоны: одна внешность на всех, имени ни у кого) или `class` (целая раса, каста или модель машины, описанная тем, что общего у любого её представителя). Различие не косметическое: скомпилированный `visual_prompt` подставляется вместо имени в каждом кадре, поэтому у группы он обязан быть одной фигурой в единственном числе и без единой личной приметы — иначе «трое стражей» отрисуются как трое мужчин с одинаковым шрамом.

`configs/voices/*.toml` — самый новый вид конфига и самый непохожий на остальные: `VoiceConfig` — это карточка плюс лежащий рядом звуковой образец, и, поскольку клонирование zero-shot (обучения нет, артефакта модели нет), карточка **и есть** голос, а не ссылка на него. `text` набирается руками намеренно: расшифровка, снятая с образца распознавателем, не просто содержит ошибки — она уводит модель, и в худшем замеренном случае та начинала произносить слова ИЗ ОБРАЗЦА посреди синтезируемой строки. В `[tts]` глобального файла добавились `engine` и по подсекции на движок, а в `paths` — `models` для весов, которые качает `slopgen models`; `ContentTypeConfig.voices` по-прежнему сопоставляет языку имя голоса, но теперь это имя читает тот движок, который говорит: идентификатор из каталога или имя клона из `configs/voices/` — одно пространство имён, а какой это случай, решает наличие карточки с таким именем.

**БАЗА КАДРОВ мира** лежит в `configs/fandoms/<имя>/frames/`: по одной TOML-карточке на картинку, картинка рядом, грузится тем же `_load_dir`, что и состав. В карточке два текста, и путать их нельзя: `prompt` — английский промпт генерации, `description` — проза на языке мира для модели, подбирающей карточки к битам, и в описании стоят **имена, но никогда не внешность** — внешность уже записана один раз в `characters/<имя>.toml`, а вторая копия с ней разойдётся. Там же `targets`: именованные прямоугольники на картинке в её долях, — именно они превращают один общий план в четыре кадра (см. `pipeline/framebase`). Флага `dirty` нет: здесь нечего компилировать, артефакт — сама картинка; зато геометрия протухает, если файл под карточкой подменили, поэтому `file_sha` — контрольная сумма в духе `docs_sha`, а спрашивает о ней `card_is_stale()`. `write_frame_card()`, `frames_dir()` и `file_sha()` стоят рядом с `write_fandom()` как единственные писатели в ядре.

**КАТАЛОГ ФОРМ КУСКА** лежит в `configs/shapes/*.toml`: по файлу на каталог, в каждом несколько `[[shapes]]` — `name`, однострочное `use_when` и `ends`, ради которого весь этот вид конфига и заведён. Планировщик фандома выбирает форму на каждый ролик (`stages/fandom_script.plan_spine`), и те четыре, между которыми он выбирал раньше, были прозой внутри промпта: закрытым списком намеренно, потому что модель, которой дают выбирать форму свободно, выбирает «атмосферное исследование», а это тот самый обзор, ради предотвращения которого план и существует, — но закрытым не в том МЕСТЕ, ведь набор форм, которые мир вообще допускает, есть факт о мире. Месту с табелем обязанностей и месту с бестиарием нужны разные, и ни то ни другое не должно быть правкой кода. `ends` — то поле, из-за которого форма больше, чем ярлык: общее правило для таких кусков — один поворот поздно и потом строка, которая останавливает, — и для части форм оно просто неверно: кусок с выбором кончается САМИМ списком вариантов, виньетка кончается недоделанной. Поэтому написанное в `ends` заменяет общее правило, а `turn` делает то же с поворотом. Мир называет свой каталог строкой `shapes = "<имя>"` в `fandom.toml`, прогон перебивает это флагом `--shapes`, а `--shape` задаёт форму одного ролика принудительно — так делается серия однотипных. Всё неназванное падает в поставляемый `default`, а чекаут вообще без каталога — в две формы, определённые в коде: этого хватает, чтобы режим работал, и это сознательно не вторая копия поставляемого файла, чтобы им нечем было разойтись.
