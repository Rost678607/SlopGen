# config

**EN:** Pydantic models for every config kind (`models.py`) and the loader (`loader.py`). `ConfigStore` scans `configs/` — the global file plus content types, ads, accounts, presets, visuals profiles, LLM profiles, characters, orchestrations and fandoms — and resolves run parameters with the priority CLI > preset > account defaults > global defaults; `active_llm_profile()` picks the LLM connection. `RunParams` is the single validated object the rest of the app consumes: besides the obvious knobs it carries the ad-hoc `manual_ad` / `manual_visuals` / `manual_cast` / `manual_orchestration` built in the TUI, the `breakpoints` a run should park on, the content controls (`visual_notes`, `visual_style`, `clean_subtitles`) and the montage `filters` — `{effect: dose}` laid over the finished cut (see `media/filters`), which unlike the other two is asked of ffmpeg rather than of a model, and so holds in every mode and from every source. For fandom mode it adds `fandom` (the world's folder name) and `fandom_voice` (`resident` / `chronicler`); everything the drama block means means the same there, `scenario` included — it is just a brief about a world rather than a plot.

**In a visuals profile, WHO supplies the material is orthogonal to WHAT it is.** `manual = true` is a flag on the background (and on the foreground) rather than a source of its own, because the operator can step into either family and what they end up doing differs: a `stock_*` source found by hand is a **search** (slopgen briefs them and hands over queries), an `ai_*` source made by hand is a **generation** (slopgen writes the prompt), and `local_*` ignores the flag entirely — those files are already on disk. `manual_kind(source, manual)` is the one place that mapping lives, returning `"search"` / `"generate"` / `""`, and both footage stages route on its answer. `ai_model` is ignored wherever `manual` is set: there is no generator left to name. This replaced an earlier `ai_model = "manual"` hack, which could only express the generation half and hid a question about supply inside an answer about generators.

**Fandoms are the one config kind that is a DIRECTORY** (`configs/fandoms/<name>/`), so `_load_fandoms` does the walking instead of `_load_dir`: the folder name is the identity whatever the TOML says, `fandom.toml` is optional (a folder of markdown is a valid world with every default), and the world's own cast is loaded from `<folder>/characters/` with the same `CharacterConfig` the global library uses. `fandom_docs` resolves the reading order (`docs`, else every `*.md` sorted; a name pointing at nothing is skipped rather than taking the world down), `read_lore` concatenates the documents under their own filename headings so both the writer and the librarian tool can tell one from another, `lore_sha` hashes that text, and `write_fandom` persists the settings back (runtime-only `root`/`cast` are excluded by the model). `FandomConfig.canon` is to the lore what `CharacterConfig.visual_prompt` is to an appearance — an LLM-compiled digest — except that its freshness is a checksum (`docs_sha`) rather than a `dirty` flag, because lore gets edited in an outside markdown editor where nothing would ever raise a flag. `envfile.py` writes single variables into `.env` (API keys entered in the TUI).

**RU:** Pydantic-модели всех видов конфигов (`models.py`) и загрузчик (`loader.py`). `ConfigStore` сканирует `configs/` — глобальный файл плюс типы контента, реклама, аккаунты, пресеты, профили видеоряда, профили нейронок, персонажи, оркестрации и фандомы — и резолвит параметры прогона с приоритетом CLI > пресет > дефолты аккаунта > глобальные; `active_llm_profile()` выбирает LLM-подключение. `RunParams` — единый валидированный объект, которым пользуется всё остальное: кроме очевидных ручек он несёт ad-hoc `manual_ad` / `manual_visuals` / `manual_cast` / `manual_orchestration` из TUI, список `breakpoints`, на которых прогон должен встать, контентные ручки (`visual_notes`, `visual_style`, `clean_subtitles`) и монтажные `filters` — `{эффект: доза}`, накладываемые на готовый монтаж (см. `media/filters`); в отличие от первых двух это просят не у модели, а у ffmpeg, поэтому работает во всех режимах и с любым источником. Для режима фандома добавляются `fandom` (имя папки мира) и `fandom_voice` (`resident` / `chronicler`); всё остальное из драмовского блока значит там ровно то же, включая `scenario`, — просто это бриф про мир, а не про сюжет.

**В профиле видеоряда КТО поставляет материал ортогонально тому, ЧТО это за материал.** `manual = true` — это флаг на фоне (и на переднем плане), а не отдельный источник: оператор может вмешаться в любое семейство, и делает он при этом разное. Найденный руками `stock_*` — это **поиск** (слопген пишет задание и выдаёт запросы), сделанный руками `ai_*` — это **генерация** (слопген пишет промпт), а `local_*` флаг игнорирует вовсе: эти файлы уже лежат на диске. `manual_kind(source, manual)` — единственное место, где живёт это соответствие; он возвращает `"search"` / `"generate"` / `""`, и обе стадии видеоряда ветвятся по его ответу. `ai_model` игнорируется везде, где выставлен `manual`: называть больше нечего. Это пришло на смену костылю `ai_model = "manual"`, который умел выразить только генерацию и прятал вопрос о поставщике внутри ответа про генераторы.

**Фандом — единственный вид конфига, который является ДИРЕКТОРИЕЙ** (`configs/fandoms/<имя>/`), поэтому его обходит `_load_fandoms`, а не `_load_dir`: имя папки и есть тождество, что бы ни было в TOML; `fandom.toml` необязателен (папка с markdown — уже валидный мир со всеми дефолтами); собственный каст мира грузится из `<папка>/characters/` тем же `CharacterConfig`, что и общая библиотека. `fandom_docs` определяет порядок чтения (`docs`, иначе все `*.md` по алфавиту; имя, указывающее в никуда, пропускается, а не роняет мир), `read_lore` склеивает документы, каждый под заголовком со своим именем файла, чтобы и сценарист, и инструмент-архивариус отличали один от другого, `lore_sha` считает по этому тексту контрольную сумму, а `write_fandom` пишет настройки обратно (рантайм-поля `root`/`cast` исключает сама модель). `FandomConfig.canon` — это для лора то же, что `CharacterConfig.visual_prompt` для внешности, скомпилированная нейронкой выжимка, с одной разницей: свежесть определяется контрольной суммой (`docs_sha`), а не флажком `dirty`, потому что лор правят во внешнем markdown-редакторе, где никакой флажок не поднимется. `envfile.py` пишет отдельные переменные в `.env` (ключи, введённые в TUI).
