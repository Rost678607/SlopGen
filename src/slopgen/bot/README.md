# bot

**EN:** The Telegram front door — `slopgen bot`. Three parts in one process, and the reason they share it is the supervisor: a run started by a button in the chat and a run started in the Mini App are the SAME object in the same list, so stopping one from the phone stops what the panel is showing. Two processes would have been two lists of runs that disagree about reality, and the disagreement surfaces as "I pressed stop and nothing happened". `service.py` is the process — uvicorn on a thread, the watch on another, long polling in the main one where Ctrl-C reaches it; `chat.py` is the conversation; `auth.py` is the guest list and the Mini App's signature check; `tunnel.py` is the free public address that makes the Mini App possible at all. Nothing in `pipeline/`, `config/` or `media/` knows this exists, exactly as nothing in them knows about the terminal or the browser.

**The Mini App is the panel, not a copy of it.** Telegram opens a web page inside the client if it is served over HTTPS, so the button opens the very same FastAPI app `slopgen web` serves. Signing in needs no password: Telegram hands the page an `initData` query string stamped with an HMAC only a holder of the bot token could produce, `/api/tg-login` verifies it against the token and then against the same allow-list the chat is filtered by, and hands back a session. That session travels three ways — a cookie, an `X-Slopgen-Token` header and a `?t=` parameter — because inside Telegram Web the page is a third-party iframe whose cookie the browser may discard, and because `<img>`, `<video>` and `EventSource` cannot send a header at all. The presence of a bot also closes the anonymous door: without a password the panel is loopback-only and open, which is right at a desk and catastrophic at the far end of a tunnel, so `create_app(tg=…)` makes a session mandatory.

**The address is disposable on purpose.** A machine under a desk has no domain and no certificate; `cloudflared tunnel --url` gives one away, terminating TLS at Cloudflare and forwarding to loopback, with no account, no inbound port and no certificate to renew. The catch is that every restart of the tunnel is a new `*.trycloudflare.com` name — which only matters for a URL somebody has to remember, and nobody here does: the button is rebuilt from whatever the tunnel currently says and the owner gets one message when it moves. Set `[bot].public_url` to your own address and no tunnel is raised; everything else works identically, because the rest of the bot only ever asks "what is the address right now".

**What the chat is for is material.** The panel is the whole program, so the chat is deliberately not a second copy of it: it is the part worth having on a phone with one hand free. Starting a run means picking a mode and a world and letting every other setting be what the configs already say — the parameters are built by `web/params.py`, the same functions the browser's forms go through, so a run started by a button and a run started by a form are built the same way. The part that genuinely belongs in a chat is the other direction: this pipeline asks a person for pictures at unpredictable hours, and answering a parked run is a reply with a photo attached. The bot names each owed shot in its own message, a reply lands on that shot, a plain send lands on whichever it last pointed at, and the file goes into the run's inbox under the shot's id — the same place `slopgen gather` and the panel's upload put it, so nothing afterwards depends on the bot having been involved. A shot with a file already in the inbox counts as owed no longer even though the manifest still says pending, because the manifest is only rewritten when the run picks the inbox up.

**Nobody is served who is not on the list.** `[bot].allow_file` is plain text, one Telegram id per line, re-read whenever it changes — adding somebody is an edit, not a restart — and the first id is the owner, who gets the notices nobody asked for (a tunnel that moved, a run that failed, a finished video). A stranger gets exactly one reply and it contains their own id, which is the shortest path from "I made a bot" to "it answers me" and tells them nothing else about the machine. The watch that reports finished, failed and parked runs polls rather than subscribes, deliberately: the supervisor's event stream is per-run and live, while this has to cover runs adopted off disk at startup and runs started from somebody else's browser. Its first sight of any run is silent — announcing forty finished videos from last week is how a bot gets muted on its first day.

**RU:** Парадная в Telegram — `slopgen bot`. Три части в одном процессе, и делят они его ради супервизора: прогон, запущенный кнопкой в чате, и прогон, запущенный в мини-приложении, — это ОДИН объект в одном списке, поэтому «стоп» с телефона останавливает то, что показывает панель. Два процесса были бы двумя списками прогонов, расходящимися в показаниях, а расхождение выглядит как «нажал стоп, и ничего не произошло». `service.py` — сам процесс: uvicorn в потоке, дозор в другом, длинный поллинг в главном, куда достаёт Ctrl-C; `chat.py` — разговор; `auth.py` — список допущенных и проверка подписи мини-приложения; `tunnel.py` — бесплатный публичный адрес, без которого мини-приложения не бывает вовсе. Ни `pipeline/`, ни `config/`, ни `media/` про это не знают — ровно так же, как не знают про терминал и про браузер.

**Мини-приложение — это и есть панель, а не её копия.** Telegram открывает веб-страницу внутри клиента, если её отдают по HTTPS, поэтому кнопка открывает то же самое FastAPI-приложение, которое отдаёт `slopgen web`. Пароль не нужен: Telegram кладёт странице строку `initData`, подписанную HMAC, который умеет посчитать только держатель токена бота; `/api/tg-login` проверяет подпись против токена, а потом id — против того же списка допущенных, что фильтрует чат, и выдаёт сессию. Сессия ездит тремя способами — кука, заголовок `X-Slopgen-Token` и параметр `?t=`, — потому что внутри Telegram Web страница живёт в стороннем iframe, чью куку браузер вправе выбросить, а `<img>`, `<video>` и `EventSource` заголовков не шлют вовсе. Само наличие бота ещё и закрывает анонимный вход: без пароля панель сидит на локалхосте и открыта всем, что верно за своим столом и катастрофично на том конце туннеля, поэтому `create_app(tg=…)` делает сессию обязательной.

**Адрес одноразовый — и это не проблема.** У машины под столом нет ни домена, ни сертификата; `cloudflared tunnel --url` выдаёт их даром: TLS завершается на Cloudflare, дальше идёт на локалхост, без аккаунта, без открытого порта и без сертификата, который надо продлевать. Плата — новое имя `*.trycloudflare.com` на каждый перезапуск туннеля. Это мешало бы, если бы адрес надо было помнить, но его никто не помнит: кнопка строится из того, что туннель говорит прямо сейчас, а владельцу приходит одно сообщение, когда адрес переехал. Есть свой домен — впиши его в `[bot].public_url`, и туннель не поднимается вовсе; всё остальное работает так же, потому что весь остальной бот только и спрашивает «какой адрес сейчас».

**Чат нужен ради материала.** Панель — это вся программа целиком, поэтому чат нарочно не её копия: это та часть, которую стоит иметь на телефоне, когда свободна одна рука. Запустить прогон — значит выбрать режим и мир и дать всем остальным настройкам быть такими, какими их уже описали конфиги: параметры собирает `web/params.py`, те же функции, через которые проходят формы браузера, — поэтому прогон от кнопки и прогон от формы собраны одинаково. А по-настоящему чату принадлежит обратное направление: этот конвейер просит у человека картинки в непредсказуемое время, и ответ застывшему прогону — это сообщение с фотографией. Бот называет каждый недостающий кадр отдельным сообщением, ответ на него попадает в этот кадр, а присланный просто так — в тот, на который бот указывал последним; файл ложится во входящие прогона под id кадра — туда же, куда его кладут `slopgen gather` и загрузка из панели, так что дальше уже ничто не зависит от того, участвовал ли бот. Кадр, для которого файл уже лежит во входящих, перестаёт числиться недостающим, даже если манифест ещё говорит «ждём»: манифест переписывается только когда прогон эти входящие заберёт.

**Никого не обслуживают вне списка.** `[bot].allow_file` — обычный текст, по одному Telegram-id в строке, перечитывается при изменении файла (добавить человека — это правка, а не перезапуск), а первый id — владелец: ему уходят уведомления, которых никто не просил (адрес переехал, прогон упал, ролик готов). Чужой получает ровно один ответ, и в нём его собственный id — кратчайший путь от «я завёл бота» до «он мне отвечает», и больше про машину он оттуда не узнаёт ничего. Дозор, который сообщает о готовых, упавших и застывших прогонах, опрашивает, а не подписывается, и это нарочно: поток событий супервизора — на один прогон и только живой, а покрыть надо и прогоны, подобранные с диска при старте, и запущенные из чужого браузера. Первый взгляд на любой прогон молчит: объявить сорок роликов, доделанных на прошлой неделе, — верный способ получить «выключить уведомления» в первый же день.
